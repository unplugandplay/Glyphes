# openCypher TCK subset — the committed denominator for gate C1 (docs/TESTING.md §5).
#
# Format, tab-separated:
#   id <TAB> in|out <TAB> query <TAB> expectation
#
# A `query` column may end with ` -- {json}` to supply parameters for that
# row; everything before the separator is the query. An optional fifth
# column says where the row runs: `fixture` (the default, the read-only
# committed graph) or `write:<verify-sql>` — run the write in its own
# transaction against a disposable in-memory graph seeded with two
# `:Seed {v: 1}` and `:Seed {v: 2}` nodes, commit, then run the verifying
# query and compare *that* against the expectation. Write rows cannot use
# the fixture (the denominator would depend on how many times the suite has
# run), and they verify in a later statement because pin C4 says a query's
# reads never see its own writes.
#
# `in`  — in the 0.1 contract. `expectation` is the result as a JSON array of
#          rows, each row a JSON array of column values. Run against
#          tests/fixtures/social.glyph (six Person nodes, one Company, KNOWS
#          and WORKS_AT edges; Frank has no age).
# `out` — out of contract. `expectation` is the substring the refusal message
#          must contain. Out-of-contract rows are NEVER counted as passes
#          (TESTING.md rule 2); they are the implementation queue (rule 3).
#
# This subset may only shrink by explicit decision with a recorded reason
# (TESTING.md rule 4). C1 requires >= 95% of the `in` rows to pass.
